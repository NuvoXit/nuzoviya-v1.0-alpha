"""
FLASK FRAMEWORK OVERVIEW & DEPLOYMENT DOCUMENTATION
=====================================================

Flask is a lightweight, flexible Python web framework built on Werkzeug and Jinja2 templates.
It follows the WSGI (Web Server Gateway Interface) standard and uses a micro-framework approach,
allowing developers to build scalable web applications with minimal boilerplate code.

HOW FLASK WORKS:
1. Application Factory: The Flask(__name__) instance creates the core application object that handles
   routing, request/response processing, and middleware management.

2. URL Routing: Flask uses decorators (@app.route()) to map URLs to Python functions (view functions).
   When a client requests a URL, Flask matches it against registered routes and executes the corresponding handler.

3. Request Context: Flask manages application and request contexts, allowing view functions to access
   current request data (headers, JSON body, query parameters) via context-local proxies like request and g.

4. Response Handling: View functions return responses that Flask serializes. JSON responses are automatically
   converted using jsonify(), which sets proper Content-Type headers and handles data serialization.

5. Database Integration: SQLAlchemy ORM (Object-Relational Mapping) abstracts database interactions. Models
   define database schemas as Python classes, and db.session manages transactions for CRUD operations.

6. CORS (Cross-Origin Resource Sharing): Flask-CORS middleware enables the backend to accept requests from
   frontend applications running on different origins (like http://localhost:5173), managing preflight requests
   and setting appropriate HTTP headers.

7. Admin Dashboard: Flask-Admin provides a built-in admin interface for managing database records through
   a web UI, eliminating the need for raw SQL commands or separate admin tools.

DEPLOYMENT BEST PRACTICES:
- Use a production WSGI server (Gunicorn, uWSGI) instead of Flask's development server
- Set FLASK_ENV=production and disable debug mode
- Store sensitive configuration (SECRET_KEY, database credentials) in environment variables, not in code
- Use a reverse proxy (Nginx) to handle SSL/TLS termination and load balancing
- Enable request logging and monitoring for production debugging
- Configure proper database migrations with Alembic for schema versioning
"""
